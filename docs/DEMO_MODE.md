# DEMO_MODE — قواعد وضع العرض التجريبي

## 1. الهدف
- تمكين الفريق من تقييم كامل رحلة المستخدم دون أي اتصال خارجي أو دفع حقيقي.
- جعل كل "واقعية" مرئية للمستخدم **موسومة صراحةً** كتجريبية.

## 2. المبادئ
1. **لا شبكة إلزامية:** التطبيق يعمل بلا إنترنت، والبيانات من Mock.
2. **وسم واضح:** كل شاشة تبرع تحمل شريط `DEMO`.
3. **لا مدفوعات حقيقية:** `PaymentProvider` الوحيد المتاح هو `MockPaymentProvider`.
4. **لا مفاتيح:** لا `API_KEY` حقيقي مطلوب لتشغيل Demo.
5. **تصفير:** زر "تصفير Demo" يعيد البيانات إلى الحالة الابتدائية.
6. **حماية:** بيانات Demo وهمية فقط، ولا تُنسخ من إنتاج.

## 3. قواعد البيانات
- مستخدمون وهميون معرفون بأسماء عامة.
- طلبات مساعدة لعينة محدودة (على الأقل 3 حالات: جديدة/قيد المراجعة/مكتملة).
- مستندات وهمية مولّدة (صورة رمادية تحمل كلمة `SAMPLE`).
- مبادرات عرس/سوق/وظائف تجريبية (≥ 3 لكل وحدة).

## 4. قواعد الإيصالات والأثر
- كل إيصال: `RECEIPT_ID: DEMO-…` + ختم `DEMO — غير حقيقي`.
- شريط الأثر: يمكن عرضه، لكن مع وسم `محاكاة`.
- لا يُدَّعى جمع مبلغ حقيقي، ولا يُعرض كرقم موثوق.

## 5. فصل البيانات
- مساحة تخزين منفصلة (`@demo/*`) عن أي مساحة إنتاجية.
- لا يُسمح بنسخ بيانات Demo إلى بيئة إنتاج، والعكس.

## 6. معايير قبول Demo
- يعمل بالكامل بلا شبكة.
- زر التصفير يعمل ويُعيد الحالة.
- كل مسار مالي/عيني واضح الوسم.
- لا مسار يتيح إدخال بيانات دفع حقيقية.

## 7. الترقية إلى بيئة اختبار حقيقية (لاحقاً)
- تفعيل `SupabaseAuthProvider` أو ما يعادله عبر `FeatureFlag`.
- إخفاء كل تسميات Demo، والاحتفاظ بالإيصالات الحقيقية في طبقة منفصلة.
- تتويج ذلك في مرحلة مستقلة (Phase 08+)، وليس ضمن هذه المرحلة.
