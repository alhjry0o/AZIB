# USER_FLOWS — التدفقات الرئيسية

> كل التدفقات تُنفّذ أولاً في Demo Mode. أي خطوة تتطلب تكاملاً خارجياً تُحاكى عبر Mock Adapter.

## 1) تسجيل الدخول
1. Guest يفتح التطبيق → شاشة ترحيب عربية RTL.
2. يختار: تسجيل دخول / إنشاء حساب / تجربة Demo.
3. Mock Auth: OTP تجريبي (`123456`) أو بريد وهمي.
4. إنشاء جلسة → تحميل الدور → توجيه للواجهة المناسبة.
5. يُسجَّل حدث `auth.login` في Audit (بلا بيانات حساسة).
- **حالات خاصة:** محاولة فاشلة → قفل مؤقت تجريبي؛ تسجيل خروج → تصفير محلي.

## 2) طلب المساعدة (Beneficiary)
1. تسجيل الدخول كمستفيد.
2. تعبئة بروفايل مختصر (اسم مستعار + احتياج + منطقة عامة).
3. إنشاء طلب `draft` → حفظ محلي (Offline).
4. رفع مستندات إلى `Secure Vault` (مشفّرة).
5. إرسال → حالة `submitted`.
6. تشغيل `Eligibility Engine` → ناتج **استشاري** (`recommendation`).
7. توجيه تلقائي إلى Reviewer → `under_review`.
8. قرار بشري: `approved / rejected / needs_info` مع تبرير.
9. إشعار المستفيد (آمن، لا يكشف للغير).
10. عند الموافقة → تنسيق التنفيذ عبر Admin → `fulfilled`.
- **حماية:** هوية المستفيد محجوبة عن كل من ليس Reviewer/Admin المصرّح.

## 3) العرس الجماعي
1. Guest/Beneficiary يدخل صفحة العرس الجماعي (تعريف + شروط).
2. تسجيل اهتمام → `application.draft` مع بيانات هوية محجوبة.
3. موافقة صريحة على الخصوصية (نص عربي واضح).
4. مراجعة بشرية → `accepted / waitlisted / declined`.
5. إشعار آمن، لا قائمة عامة للمتقدمين.
6. إدارة الدعم (هدايا/تجهيزات) عبر Admin، دون دفع حقيقي.
- **قيد صارم:** لا تعارف فردي، ولا كشف هوية لأي طرف.

## 4) التبرع (Demo)
1. Donor يختار مبادرة (طلب/عرس/سوق).
2. شاشة تأكيد تحمل وسم `DEMO — لا يتم أي دفع حقيقي`.
3. اختيار المبلغ التجريبي (قيم جاهزة).
4. تأكيد → `PaymentProvider` **Mock** يُعيد `demo_success`.
5. إيصال يحمل وسم `DEMO` + رقم مرجعي وهمي.
6. يُظهر التطبيق "الأثر التجريبي" على المبادرة (شريط تقدم وهمي).
- **قيد صارم:** لا أدخال بيانات بطاقة، لا مفاتيح دفع، لا اتصال بأي بوابة.

## 5) سوق الخير
1. مستفيد/متبرع ينشر عنصراً (غير نقدي مباشر).
2. مراجعة بشرية للعنصر (سلامة/ملاءمة).
3. المستفيد يطلب العنصر → يُوجَّه الطلب لوسيط بشري.
4. الوسيط ينسّق، لا يتم تبادل بيانات مباشر.
5. إغلاق العنصر بعد التسليم → Audit.
- **قيد:** لا أسعار نقدية بين المستفيد والبائع، ولا دفع حقيقي.

## 6) الوظائف
1. Admin/Partner ينشر فرصة عمل.
2. المستفيد يقدّم بسيرة **مجهولة الهوية**.
3. المراجع البشري يرشّح، ويرسل للشركة ملفاً مجهّلاً.
4. الشركة تُبدي اهتماماً → كشف الهوية يتم فقط بموافقة صريحة من المستفيد.
5. إغلاق الفرصة → Audit.

## 7) تدفق عام: Governance
- كل قرار بشري → Audit entry (فاعل، وقت، سبب، إصدار قواعد).
- كل تغيير في قواعد الأهلية → إصدار جديد بتاريخ سريان.
- كل تعارض مصالح → تسجيل + إعادة تعيين.
